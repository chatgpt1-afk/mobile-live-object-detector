桌面商品测量 v1.0
中文操作指南

独立测试版本：一部手机、手机支架、卷尺、办公室桌面、校准纸。无付费服务、无数据库服务器、无登录。

先了解这一版能做什么

空桌参考纸建立尺寸比例，空背景帮助检测商品。商品照片不必露出参考纸。系统把当前摆放厚度视为 0 至最高厚度之间的深度范围，计算保守空间估计，而不是把整件商品统一缩小到最高面。

这一版没有通过实物精度验证。所有记录均保留 Review Required。目标是避免低估、尽量不超过 +5%；这里没有“绝不低估”的保证。镜头畸变、距离输入误差、漏掉轮廓、物品变形等未被严格界定。请先用实物验证，再让员工批量使用。

一、怎样打开系统

电脑：直接检查界面与上传照片

  1. 解压 ZIP 到一个全新的文件夹，保留里面文件的相对位置。
  2. 双击 index.html。可以上传三类照片测试。不需要安装 Python。
  3. 如果浏览器限制本地记录存储，双击 start_local_server.bat；它使用 Windows PowerShell 在本机打开 http://localhost:8765。保持窗口开着，Ctrl+C 停止。此地址只给该电脑使用。

手机：相机需要 HTTPS 网址

手机不能靠双击 ZIP 或访问电脑的普通 HTTP 地址开启网页相机。请用新的静态网站地址承载本版本。

  1. 在 GitHub 创建一个全新的仓库，例如 tabletop-product-measure，不要上传到旧测量系统仓库。
  2. 用 Add file → Upload files 上传解压文件夹内的文件。必须让 index.html、app.js、core.js、exports.js、styles.css 位于仓库根目录。不要上传 ZIP 本身。
  3. 进入 Settings → Pages，选择从分支发布（Deploy from a branch），选择 main 和 / (root)，保存。具体文字可能随 GitHub 界面变化。
  4. 发布完成后，在手机 Chrome / Safari 打开显示的 https:// 地址，允许相机权限。不要在聊天软件内置浏览器中测试。

若公司不允许公开仓库，使用公司已有的 HTTPS 静态网站目录。网页源代码是静态文件；照片和记录由浏览器本地处理，没有代码把商品照片上传到服务器。公开仓库也不能放公司照片或备份文件。

本 ZIP 尚未发布到网址。不要把 localhost:8765 输入手机；它在手机上指向手机自己。新版不注册 Service Worker，避免与旧版缓存混用。

  • 镜头垂直向下，支架稳固。使用普通主摄；不要用超广角、变焦或人像模式。
  • 纸张和商品长宽方向都尽量与画面横纵方向对齐，商品尽量居中。拍到完整商品，并留边缘余量。
  • 办公室灯先保持现状。避免手机／手挡光、直射阳光变化；不要开手机闪光灯。
  • 最高厚度是当前摆放从桌面到最高点的垂直距离。不要压扁软袋。

示例：镜头到桌面 60 cm、平躺商品最高点 5 cm。输入 Distance = 60、Maximum thickness = 5。不是输入镜头到商品 55 cm，也不是输入支架高度。

三、打印校准纸

  1. 打开 reference-15x10cm.pdf。A4、Actual Size / 100%，关闭 Fit / 缩放。
  2. 用卷尺验证黑框最外沿：宽 15 cm、高 10 cm。两者都要检查。
  3. 若尺寸不同，重新打印，或在 Reference width / height 输入实际值。纸张尺寸不能只凭 A4 名称推定。
  4. 不要折弯纸张。校准时将整张黑框放在画面中央，横边水平，纵边垂直。

大商品需要把手机抬高时，可用更大的已知尺寸矩形代替，但必须输入实际宽高。参考框在画面中太小会被拒绝。系统可建议黑框位置；四角仍需要你确认。

四、第一件商品：逐步操作

  1. 点击 Start Measurement，输入 Barcode。保留前导零。条码相机扫描取决于浏览器支持；也可手输或用外接条码扫描枪。
  2. 选择 Front / Side / Top。下面的提示说明当前水平和垂直对应哪个物理尺寸。
  3. 点击 Open Camera。先试放商品，调整支架让全件入镜，再移走商品。用卷尺测量镜头到桌面的垂直距离，填入 Lens → desk。
  4. 放参考纸，点击 1 · Capture Reference。点击 Suggest Corners 或依次手动点：左上、右上、右下、左下的黑框外角。点位可拖动。确认打印尺寸后点击 Confirm Calibration。
  5. 取走参考纸，不动手机和桌面。点击 Live Preview 回到实时画面，再点 2 · Set Empty Background。
  6. 放回商品，输入当前姿态的 Maximum thickness。Extra clearance 默认 2%，这是额外余量，不代表精度保证。
  7. 点击 Live Preview，再点 3 · Capture Object。自动检测会给出建议框。
  8. 检查框是否包含整个商品。拖四角调整大小、拖内部移动；Draw New Frame 后拖出新框；Undo / Redo 可撤销或恢复。
  9. 勾选“完整商品已在框和照片中”，点击 Confirm Frame & Measure。若框碰到图片边缘，系统拒绝测量，必须重拍。
  10. 检查数值及 Review Required 原因。点击 Add / Replace This View。
  11. 翻转商品，选择下一视图、重新输入当前厚度，再拍第二张。手机不动且灯光稳定时可以复用校准与背景。手机位置变了则点击 Reset Setup / Phone Moved，重做步骤 4、5。
  12. 两张视图覆盖 L/W/H 后，点击 Save Current Record。查看 History 不会强迫输入下一件条码。Next Item 在未保存时会询问保存／丢弃／取消。

本版是拍照后自动检测与人工确认；不是连续实时跟踪。需要完整轮廓。先前讨论的“侧照可不拍到顶部”未开放，因为无法可靠判断最大宽度是否在画面外。

这是同一部手机保持向下拍摄、翻转商品的流程，不必另买第二部手机或侧面支架。若商品无法稳定放置，先找可靠支撑，或标记待人工复核；不要让手进入测量框。L/W 的定义必须由公司事先统一，瓶子等没有天然方向的商品也要统一。

推荐 Front + Side；也可以 Front + Top。重复尺寸取较大值。只拍一张时第三个尺寸保持空白，记录标记 Missing physical dimension。厚度输入只参与几何计算，不会冒充系统测出的第三个尺寸。

六、看到 Review Required 怎么处理

本原型的所有记录都需要实物验证。Depth-scale budget 只反映深度范围和额外余量，不包含四角点击误差、畸变、距离误差、检测遗漏、上取整等，不能当作完整误差率。

  • Depth-scale budget exceeds 5%：手机相对厚度太近。提高支架、更新距离并重新校准。界面显示的建议距离仅针对该预算，不是最终精度保证。
  • Frame touches edge：商品可能被截断；必须移远重拍，不能用已测 Height 为缺失区域作保证。
  • Scene changed：边缘背景差异明显。检查手机移动、光照、参考纸未移走等；重做校准和空背景。均匀背景上的移动可能检测不到，不能只依赖系统提醒。
  • Reference looks tilted：检查四角顺序、纸张平整、主摄、拍摄角度和参考框实际宽高。校准检查只是筛查，不替代完整镜头标定。

举例：60 cm 距离、5 cm 厚度、2% 余量，该预算约 11.3%，因此超出 +5% 目标。把支架升到约 175 cm 才能把这项预算降至约 5%。这说明严格保守估计的代价：厚商品在普通办公距离下很可能仍需复核。系统不会偷偷改用最高面修正来让数值看似准确。

七、阴影和检测调节

本版有轻阴影抑制，但默认关闭，避免将黑色商品边缘当作阴影删除。勾选 Reduce mild shadows 后需要再次 Detect Again，并检查所有边缘。深色、透明、反光或接近桌面颜色的商品，优先手动调整框。

  • 浅色小商品找不到：降低 Sensitivity threshold，或降低 Minimum object area。
  • 桌面杂点被识别：提高 threshold / Minimum object area。
  • 框包含浅阴影：尝试阴影抑制，或手动收至真实轮廓，但绝不能切掉商品。
  • 软袋、把手和零散部件：自动框可能只包含最大区域；手动扩大，包含整件商品。

八、保存与导出

  • 重复 Barcode：Replace All for Barcode 替换该条码全部旧记录；Keep Duplicate 保留重复；Cancel 取消。仅在实际保存成功后才替换。
  • Generate Excel：Products 表包含 Barcode、L/W/H、状态；Views and Review 表包含每张照片的方向、距离、厚度、余量及预算。真正的 XLSX 文件，条码按文字保存。
  • Generate Image ZIP：包含 Image 文件夹，每视图一张矩形裁剪商品照，没有绿色框。矩形内的背景不会被抠掉。文件名包含条码、物理轴和尺寸、日期，不含时间；同名文件加序号避免覆盖。
  • Generate Backup JSON：完整备份照片和记录。换设备后可 Import Backup；相同记录 ID 合并更新。Excel 不用于恢复完整记录。
  • 生成后出现分享／下载选择，不会自动打开文件。手机分享位置由系统分享面板决定；若浏览器不支持分享，请 Download 后在文件管理器分享。
  • 浏览器不能保证直接写入相册。图片保存在本地记录中，由你导出 ZIP。清理浏览器数据、换浏览器或换网址会使本地历史不可见；及时备份。

九、交给员工前的实物测试

  1. 选最小、最大、最高的硬盒，以及瓶子、软袋、深色和亮面商品。
  2. 卷尺测量实物真实最大 L/W/H，记录为基准。使用实际排货姿态；软包装不要压缩。
  3. 每件至少重复 3 次，覆盖不同距离和厚度，每次移动支架都重校准。
  4. 逐项检查 实际尺寸 ≤ 系统尺寸 ≤ 实际尺寸 × 1.05。任意尺寸低估，或超出 5%，都不能当作合格。
  5. 使用真实货架间隙验证，并考虑商品取放所需空隙。验证失败时保留人工尺寸，不要把原型估计直接导入正式排货。

本包的自动测试验证数学逻辑与文件格式；没有用你的手机和真实商品完成实测。旧版系统未修改。

技术说明与来源

纯 HTML/CSS/JavaScript，无第三方在线脚本。检测基于背景颜色差异、连通区域与可选轻阴影排除；阴影抑制是本版启发式代码，不是内置 OpenCV MOG2。空桌四角建立平面映射；镜头垂直桌面、主点近似图片中心。输入最高厚度定义深度区间，计算各框角沿相机射线在区间两端的桌面平行坐标，再取包围尺寸，加余量并上取整。未执行完整相机内参／镜头畸变标定。若手机自动换镜头、裁切或变焦，必须重校准；同分辨率不能证明镜头没变。

几何基础：OpenCV Camera Calibration and 3D Reconstruction。相机权限基础：MDN getUserMedia。静态发布参考：GitHub Pages。
